Project 4: Image Warping and Mosaicing

Overview

In this project, we created mosaics of multiple images to create a panamoric like view of the scene. To do so, we used image projection techniques after picking corresponding points in both images. In Part B, we automated the point picking by detecting, describing, and matching features, then using RANSAC to find a robust homography.

A.2: Recover Homographies

As seen in class and specified by the project specifications, the homography is computed using the following function. In essence, we are creating a system of linear equations from the points we clicked in both images (with each point contributing two equations to the system). However, since the SoE is overdetermined, we use least squares to find a solution. 

def computeH(im1_pts, im2_pts):
    src_normalizer, dst_normalizer = normalization_matrix(src), normalization_matrix(dst)
    A, b = build_system(apply_H(src_normalizer, src), apply_H(dst_normalizer, dst))
    h, *_ = np.linalg.lstsq(A, b, rcond=None)
    H_normalized = np.append(h, 1.0).reshape(3, 3)
    H = np.linalg.inv(dst_normalizer) @ H_normalized @ src_normalizer
    return H / abs(H[2, 2])

A.3: Warp the Images

To warp images, I used the homography matrices to generate the transformed images via inverse mapping. This was achieved by first mapping the borders of the image to see the output bounding box before then mapping every pixel of the output image to its pixel value from the original image using the inverse homography. To methods were used for sampling and were implemented from scratch as described in class: nearest neighbor and bilinear interpolation. 

def sample_bilinear(image, src_x, src_y):
    left, top = floor(src_x), floor(src_y)
    wx, wy = src_x - left, src_y - top
    top_row    = (1 - wx) * image[top, left]    + wx * image[top, left + 1]
    bottom_row = (1 - wx) * image[top+1, left]  + wx * image[top+1, left + 1]
    return (1 - wy) * top_row + wy * bottom_row

Rectification

To rectify rectangular objects taken at an angle, I clicked the four corners of the object and found the homography that maps the points into a rectangle. Then, the above image warping techniques were used to generate the fixed image.

Nearest Neighbor vs. Bilinear

At a glance the two look almost identical, but zoomed in nearest neighbor produces jagged, aliased edges. This is because neighboring output pixels are not necessarily 1-1 bijections to the source pixels, creating aliasing. Bilinear gives smoother edges but results in some blurring.

A.4: Blend the Images into a Mosaic

The procedure for each mosaic:

Each scene's images were first compared pairwise to generate homographies. These images were then warped and projected onto a shared canvas that covers the union of all warped images. These were mapped using the inverse homographies. Finally, the images were blended together to form the final mosaic.

The following three blends were implemented:

  • Overwrite: later images simply paste over earlier ones. This has some noticeable seams.

  • Feather: a weighted average using the distance-to-edge weights. No seam but ghosting for images with moving objects.

  • Two-band (Laplacian): used a laplacian pyramid with σ = 8 just like we implemented in previous projects. Only two bands were used as specified in the specs.

Blending Comparison

In the Hearst close-up, overwrite leaves a visible diagonal seam through the doorway and column. Feathering hides the seam but slightly blurs the window grilles where the two images disagree by a pixel or two. The laplacian blend achieves results similar to the feathering approach, since there are no artifacts that would cause significant ghosting. On the beach, overwrite shows a clear brightness step in the sky and keeps a lens flare from one shot. Feathering appears blurrier due to the ghosting caused by the moving waves and sky, and the two-band blend removes it almost entirely and looks cleaner.

Part B: Feature Matching for Autostitching

In this portion of the project, our goal was to achieve automatic panorama stitching in accordance with the method described in the MOPS paper. The steps were implemented in the order of the article below.

B.1: Harris Corner Detection

Harris corners were found using the provided starter code, with a minimum peak distance of 3 pixels and a relative threshold of 10-3 to throw away the thousands of weak, clustered responses. Despite this, we end up with a significant number of corners that are clustered.

To fix this, Adaptive Non-Maximal Suppression (ANMS) was implemented. For each corner, we compute its radius to the nearest corner that is significantly stronger than it. Keeping the 500 corners with the largest radii gave points that are both strong and spread out across the whole image, which ensures our distribution of features is spread out across the image.

def anms(corners, h, num_points=500, c_robust=0.9):
    strengths = h[corners[0], corners[1]]
    D = dist2(pts, pts)
    suppressed = strengths[:, None] < c_robust * strengths[None, :]
    D[~suppressed] = np.inf
    radii = D.min(axis=1)
    return corners[:, np.argsort(-radii)[:num_points]]

Without ANMS, many of the corners are on the ground and steps, but this is spread out with the use of ANMS.

B.2: Feature Descriptor Extraction

For each ANMS corner, we took a 40 × 40 window around it and sampled an 8 × 8 grid every 5 pixels. Before sampling, the image is blurred with a Gaussian (σ = 2) to avoid aliasing. Each patch is then bias/gain normalized so that matching is not thrown off by exposure differences between shots. These descriptors are axis-aligned, so there is no rotation invariance.

B.3: Feature Matching

To match features between two images, we computed the SSD between every pair of descriptors and found each feature's nearest and second nearest neighbor. Instead of thresholding the distance directly, we used Lowe's ratio test to compare our match-score between the best and second best matches. This ensures that only distinct matches are kept. Most corners had ratios close to 0 (meaning they weren't distinct matches) and only corners with ratios below 0.4 were kept.

The majority of the lines are parallel, which is a good sign, but there are still a few clearly wrong matches crossing the image. The second Foothill pair only gets 22 matches, since the right photo was taken at a different zoom and much closer to the pillars, so the patches simply don't look the same at a single scale. Notably, for the second foothill pair, even if points visually match, some of the lines are not parallel. This is expected to be due to the difference in distance from the camera for different points in the image.

B.4: RANSAC for Robust Homography

Since even a few bad matches can mess up our LS fit, we implemented 4-point RANSAC. Each iteration picks 4 random matches, computes the exact homography using computeH from Part A, and counts how many of the other matches land within 2 pixels of their partner. Samples where 3 of the 4 points are nearly collinear are skipped since they give a degenerate homography. After the loop, the homography is refit with least squares on the largest set of non-outliers. I also stop early once enough iterations have run to be 99.9% confident given the current non-outlier ratio.

def ransac_homography(pts1, pts2, n_iters=5000, eps=2.0):
    best = np.zeros(len(pts1), dtype=bool)
    for _ in range(n_iters):
        idx = rng.choice(len(pts1), 4, replace=False)
        if is_degenerate(pts1[idx]) or is_degenerate(pts2[idx]):
            continue
        H = computeH(pts1[idx], pts2[idx])
        non-outliers = np.linalg.norm(apply_H(H, pts1) - pts2, axis=1) < eps
        if non-outliers.sum() > best.sum():
            best = non-outliers
    return computeH(pts1[best], pts2[best]), best

For the Hearst sequence, I took 5 photos sweeping from left to right. So, for that sequence homographies were computed between adjacent shots and then chained together to reach the reference image.

RANSAC does a good job of removing the crossing lines from the matching step. On the beach, almost all of the non-outliers are on the sand, while most of the matches along the cliff, horizon, and sun get rejected. This makes sense since all the points in the sand are in relatively the same plane, and there were many more corners in the sand. The one failure case is the second Foothill image: only 10 non-outliers survive, all on the bulletin board and the building behind it. These points are at a very different depth than the pillars, so the resulting homography aligns the background but not the foreground. We see this impacting the resulting mosaic.

Takeaways

The most surprising part was how much the point picking matters. A single sloppy click visibly bends a seam, and adding a few extra well-spread points with least squares fixed more than any change to the blending did. I also found that blending choices matter mostly for hiding exposure differences: the two-band blend handles both the exposure step and small misalignments, where feathering trades one artifact for another.

In Part B, the coolest part was how well RANSAC worked given how simple it is as well as the impact that images with varying depths had on the results. Even with around half of the matched corners being wrong, it still found reasonably good homographies. However, for the images where there were multiple depths, the use of RANSAC resulted in the discarding of corner points that corresponded to specific depths, resulting in distorted imaging.
